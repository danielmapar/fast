# Semantic Versioning (SemVer)

The most widely adopted versioning system is **Semantic Versioning** (SemVer), which uses a three-part version number:

## Version Components

### MAJOR version
- Increment when you make incompatible API changes
- Breaking changes that require users to modify their code
- **Example:** `2.1.4` → `3.0.0`

### MINOR version
- Increment when you add functionality in a backwards-compatible manner
- New features that don't break existing functionality
- **Example:** `2.1.4` → `2.2.0`

### PATCH version
- Increment when you make backwards-compatible bug fixes
- Bug fixes, security patches, minor improvements
- **Example:** `2.1.4` → `2.1.5`
